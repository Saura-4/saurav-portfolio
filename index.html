02. Things I've Built

Roughly in the order I built them. Each one exists because of what the previous one taught me.

Chrome extension · 540+ organic users

Snip & Ask

This is where it started. I wanted to ask a question about something on my screen, and the honest options were: screenshot it, save it, switch tabs, and re-explain the context. So I built a Chrome extension that captures any region of the screen and answers questions about it — without leaving the page.

The first version was just for me. Friends encouraged me to publish it, and it's now live on the Chrome Web Store. Making it work for other people was the real education: a Guest Mode with zero setup (backed by a Cloudflare Worker I run), bring-your-own-key support for Groq, Gemini, OpenAI, OpenRouter and local Ollama, an Auto Mode that routes around single-model rate limits, and on-device OCR with Tesseract.js so text-only models can read screenshots.

the arc: idea → build → make it usable → other people use it.

FOSSEE Summer Fellowship · IIT Bombay

eSim AI Assistant

At FOSSEE I worked on the eSim AI assistant, a chatbot that helps people debug circuit simulations — and it's the project that changed how I think about LLM systems.

The existing approach leaned heavily on a local LLM to reason about circuit and netlist information directly, which meant asking the model to guess facts it was never given. I redesigned the pipeline the other way around: deterministic code extracts the circuit facts first, and the LLM is handed verified facts to explain. I also built a rule-based NgSpice error analyzer that prioritizes errors by causal dependency, so root causes surface before the failures they trigger downstream.

what clicked: an LLM doesn't always need to reason itself — give it reliable information and let it explain.

RAG framework · built from scratch

Modular RAG Evaluation Framework

After eSim, I kept thinking about the same question in a more general form: how do we give LLMs better information? I didn't want to build another RAG demo — I wanted to understand retrieval itself, and you can't do that if you can't swap the parts.

So I built the framework from scratch — no LangChain, no LlamaIndex. Indexing, chunking, retrieval, reranking, generation and evaluation are all interchangeable modules. I used it to benchmark 4 chunking strategies against 4 retrieval pipelines on BEIR SciFact, implementing Recall@k, Precision@k, MRR and NDCG@k from scratch, and to compare generation strategies — CoVe, Cited-Span and Abstain Generation — under a RAGTruth-inspired hallucination evaluation. Everything runs locally on Ollama and ChromaDB, with cross-encoder reranking.

the point: change one component, measure, and actually see what happens.

Backend · a learning project, on purpose

LLM ChatBot Backend

This one isn't an AI breakthrough, and I won't pretend it is. After working on AI systems, I realized I didn't understand the engineering underneath them well enough. So I built a chatbot backend specifically to learn it — properly, piece by piece.

FastAPI and PostgreSQL with SQLAlchemy, JWT authentication, Alembic migrations, a layered CRUD and service structure, conversation and message persistence, Redis caching, and streaming responses over SSE — containerized with Docker and deployed. The rule I set for myself: understand the mental model first, then write the code.

the engineering under an AI app, built by hand instead of assumed.
